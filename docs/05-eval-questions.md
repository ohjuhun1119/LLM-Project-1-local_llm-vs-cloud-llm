## 평가 질문 세트

**Q1 — 공지사항 요약**

입력 자료:<br/>
[사내 공지] 2026년 10월부터 재택근무 신청 절차가 변경됩니다. 기존에는 팀장 승인만 필요했으나, 앞으로는 팀장 승인 후 인사팀(김지원 대리)에게 신청서를 제출해야 합니다. 신청서는 매주 목요일까지 제출해야 다음 주 반영이 가능합니다. 문의는 인사팀 내선 1234로 부탁드립니다.

기대 결과 / 확인 항목: 변경된 절차(팀장 승인 → 인사팀 제출), 담당자(김지원 대리), 제출 기한(매주 목요일), 시행 시점(2026년 10월)이 요약에 모두 포함되는지 확인


**Q2 — 회의록 요약**

입력 자료:<br/>
[주간 회의록] 참석자: 박민수 팀장, 이서연 대리, 최동훈 사원. 신제품 A의 출시일을 11월 15일로 확정. 이서연 대리가 마케팅 자료 초안을 11월 1일까지 작성하기로 함. 최동훈 사원은 협력사 견적서를 다음 주까지 수합. 다음 회의는 10월 20일 예정.

기대 결과 / 확인 항목: 결정사항(출시일 11월 15일), 액션 아이템 2건(담당자·기한 포함), 다음 회의 일정이 누락 없이 요약되는지 확인


**Q3 — 진행 보고서 요약**

입력 자료:<br/>
[3분기 진행 보고서] 프로젝트 X는 전체 일정의 70% 완료. 개발 파트는 예정대로 진행 중이나, 디자인 파트는 인력 부족으로 2주 지연 예상. 다음 마일스톤은 12월 1일 UAT 시작. 리스크: 외부 API 연동 지연 가능성 존재.

기대 결과 / 확인 항목: 진행률(70%), 지연 요소(디자인 파트, 2주), 다음 마일스톤(12월 1일), 리스크 항목이 빠짐없이 요약되는지 확인
경계 사례 (Edge Cases)


**Q4 — 정보가 뒤섞인 문서 (담당자·날짜 다수)**

입력 자료:<br/>
[태스크포스 회의록] A안건 담당 이하늘(9/20 마감), B안건 담당 정우진(9/25 마감), C안건은 담당자 미정 상태로 다음 회의에서 재논의하기로 함. 김수현 부장은 전체 일정을 10/1로 앞당길 것을 요청함.

기대 결과 / 확인 항목: 3개 안건의 담당자·기한을 서로 섞지 않고 정확히 구분해서 요약하는지, C안건이 "담당자 미정"임을 명시하는지 확인


**Q5 — 상충되는 정보가 포함된 문서**

입력 자료:<br/>
[프로젝트 업데이트] 초안에서는 예산이 5천만 원으로 책정되었으나, 회의 중 재무팀 검토 결과 4천 2백만 원으로 하향 조정됨. 최종 승인된 예산은 4천 2백만 원임.

기대 결과 / 확인 항목: 두 금액을 나열만 하지 않고 "최종 확정된 값은 4,200만 원"이라고 명확히 구분해서 요약하는지 확인 (최신/확정 정보 우선 반영 여부)


**Q6 — 출력 형식 지시 포함**

입력 자료:<br/>
Q2와 동일한 회의록<br/>
지시문 추가: "결정사항과 액션 아이템을 표(담당자/내용/기한)로 정리해줘"

기대 결과 / 확인 항목: 실제로 표 형식으로 출력하는지, 열 구성(담당자/내용/기한)을 지시대로 지키는지 확인


**Q7 — 매우 짧은 문서**

입력 자료:<br/>
[공지] 내일 오전 10시 전체 회의 있습니다.

기대 결과 / 확인 항목: 내용이 거의 없는데도 불필요하게 살을 붙이거나 있지도 않은 안건·참석자를 지어내지 않는지 확인 (짧으면 짧은 대로 정직하게 요약)
정보 부족 · 범위 밖 사례


**Q8 — 문서에 없는 정보 질문 (예산)**

입력 자료: <br/>
Q2와 동일한 회의록<br/>
지시문 추가: "이 회의에서 논의된 예산 규모를 알려줘"

기대 결과 / 확인 항목: 회의록에 예산 언급이 없으므로 "문서에 예산 관련 내용 없음"이라고 명시하는지, 임의의 숫자를 만들어내지 않는지 확인


**Q9 — 범위 밖 질문 (문서 외부 정보)**

입력 자료: <br/>
Q3과 동일한 보고서<br/>
지시문 추가: "경쟁사는 이 프로젝트에 어떻게 대응하고 있어?"

기대 결과 / 확인 항목: 문서에 없는 내용이라 답할 수 없다고 명확히 답하는지, 모델이 알고 있는 일반 지식으로 임의 추측해서 답하지 않는지 확인


**Q10 — 문서 내 모순되는 지시 vs 실제 데이터 없음**

입력 자료: <br/>
Q1과 동일한 공지사항<br/>
지시문 추가: "이 공지의 신청서 양식(파일 형식)을 알려줘"

기대 결과 / 확인 항목: 공지에 신청서 양식에 대한 언급이 없으므로 "문서에 명시되지 않음"이라고 답하는지, 그럴듯하게 지어내지 않는지 확인

## 채점 기준
|채점 항목|성격|판정 방법|
|---|---|---|
|정확성/환각 없음|필수 통과<br/> (Pass/Fail)|문서에 없는 사실(숫자,이름,날짜 등)을 지어냈으면 즉시 Fail|
|핵심 정보 누락|필수 통과<br/> (Pass/Fail)|질문별 "기대 결과/확인 항목"에 명시된 요소가 하나라도 빠지면 Fail|
|지시/형식 준수|필수 통과<br/> (Pass/Fail)|표/bullet 등 지시된 출력 형식을 안 지키면 Fail(Q6에서 중점 확인)|
|정보 부족 시 대응|필수 통과<br/> (Pass/Fail)|Q8~Q10에서 "문서에 없음"을 명시하지 않고 추측/창작하면 Fail|
|한국어 표현 자연스러움|정성 평가(5점 척도)|어색한 번역투, 반복, 존댓말 불일치 여부를 1~5점으로 채점|
|응답 속도|정량 측정(초)|동일 질문 기준 평균 응답 시간 기록, 순위가 아닌 참고 지표로 활용|
